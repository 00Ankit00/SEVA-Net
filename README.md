# SEVA-Net

**Semantic Relevance-Driven Edge Video Analytics for Bandwidth-Adaptive Smart City Surveillance**

Team HAN24 · Guide: Dr. S. Yoganand · Computer Networks & IoT

A working prototype of **DNA-SE** (Dynamic Network-Aware Semantic Encoding): YOLOv8n
runs at the edge and the system transmits only what the network can currently
sustain — a JPEG ROI thumbnail plus JSON when bandwidth allows, compact JSON alone
when it does not. The decision is driven by an EWMA-smoothed, hysteresis-bound
reading of live link telemetry, so the stream degrades gracefully instead of failing.

---

## Quick start

```bash
pip install -r requirements.txt
python scripts/fetch_assets.py     # YOLOv8n weights + sample footage (optional)
python run_demo.py                 # dashboard opens at http://127.0.0.1:8000
```

Both fetched assets are optional. Without them the pipeline falls back to a
synthetic camera and a simulated detector and still runs end to end.

To produce report numbers with no dashboard:

```bash
python scripts/run_trial.py --duration 160 --tag review1
```

## What the demo shows

The dashboard drives the whole story in one screen:

| Panel | What to point at |
|---|---|
| **Transmission mode** (top right) | Flips HIGH ⇄ LOW live as the link changes |
| **DNA-SE decision state** | EWMA bandwidth/latency against the hysteresis band, plus the exact reason for the current mode |
| **QoS telemetry & mode timeline** | Measured vs. EWMA bandwidth, both thresholds, LOW-mode periods shaded |
| **Live event feed** | Real ROI thumbnails in HIGH mode; `IMAGE SUPPRESSED` tiles in LOW mode |
| **KPIs** | All five PRD §13 metrics, computed live |
| **Network conditions** | Preset buttons and sliders to degrade the link on demand |

**Suggested demo sequence**

1. Open the dashboard. Mode is **HIGH**, thumbnails are arriving, bandwidth saved
   already reads ~95% against the full-frame streaming baseline.
2. Click **Collapse**. Within ~2–3 s the mode drops to **LOW**, the feed switches to
   `IMAGE SUPPRESSED` tiles, and payloads fall from ~1.7 KB to ~170 B —
   *alerts keep flowing while the link is failing*, which is the core claim.
3. Click **Healthy 8 Mbps**. Mode returns to **HIGH** and thumbnails resume.
4. Click **Peak load** (2.6 Mbps). Nothing switches — the EWMA sits inside the
   hysteresis band. This is the flap-suppression result, and it is the panel
   most worth explaining to an evaluator.
5. Widen or narrow the band with the **Encoder tuning** sliders to show FR-10:
   thresholds retune live, with no restart.

## Measured results

From `python scripts/run_trial.py --duration 160`, YOLOv8n on real footage over the
scripted degradation timeline:

| KPI (PRD §13) | Result |
|---|---|
| Bandwidth saved vs. full-frame streaming | **95.6 %** (599 KB vs. 13.7 MB) |
| Average payload — HIGH mode | ~1.7 KB (JSON + ROI thumbnail) |
| Average payload — LOW mode | ~170 B (JSON only) |
| Mode-transition latency | **1.6 s** down, **3.1 s** up |
| Mode transitions in trial | 2 (both correct; no spurious flaps) |
| Median end-to-end alert latency | **34 ms** |
| Edge inference per frame | **24.6 ms** (YOLOv8n @ 480 px, CPU) |
| Payloads delivered / lost | 350 / 4 (loss during induced collapse) |

**Flap suppression**, measured separately by driving noise straddling both
thresholds for 400 samples:

| Decision logic | Mode changes |
|---|---|
| Naive single threshold, no smoothing | 190 |
| EWMA only (α = 0.3), single threshold | 100 |
| EWMA + hysteresis band (DNA-SE) | **19** |

A **10× reduction in mode oscillation** — this is what NFR-3 asks for, and it is the
cleanest single number in the project. The decomposition matters too: smoothing
alone halves the flapping, but the hysteresis band does the heavy lifting
(100 → 19). Reproduce with `python scripts/flap_comparison.py`.

Every figure above is regenerated by `scripts/run_trial.py`, which writes a JSON
report into `results/`.

## Architecture

The five PRD stages map one-to-one onto modules:

| # | Stage | Module | Requirements |
|---|---|---|---|
| 1 | Data collection | [`seva/camera.py`](seva/camera.py) | FR-1, FR-2, FR-3 |
| 2 | Edge processing | [`seva/detector.py`](seva/detector.py) | FR-4, FR-5 |
| 3 | QoS telemetry | [`seva/probe.py`](seva/probe.py) | FR-6, FR-7 |
| 4 | Semantic encoder | [`seva/encoder.py`](seva/encoder.py) | FR-8, FR-9, FR-10 |
| 5 | Dynamic output | [`seva/edge_node.py`](seva/edge_node.py) | FR-11, FR-12, FR-13 |
| — | Cloud dashboard | [`seva/cloud/server.py`](seva/cloud/server.py) | FR-14, FR-15, FR-16 |
| — | Network emulation | [`seva/link.py`](seva/link.py) | — |
| — | KPI collection | [`seva/metrics.py`](seva/metrics.py) | §13 |

Stages 2 and 3 run as concurrent asyncio tasks; stage 4 fuses their outputs before
stage 5 transmits.

### Payload contract (PRD §9)

HIGH mode — JSON plus a JPEG-compressed ROI crop:

```json
{"mode":"high","event":"intrusion","conf":0.92,"bbox":[x,y,w,h],
 "thumbnail":"<base64-jpeg>","ts":"2026-09-08T10:15:03Z"}
```

LOW mode — the image key is dropped entirely, not emptied:

```json
{"mode":"low","event":"intrusion","conf":0.92,"ts":"2026-09-08T10:15:03Z"}
```

### Mode-switch logic (PRD §10.2)

`EWMA_t = α·x_t + (1−α)·EWMA_{t−1}` over both bandwidth and latency, then:

- **HIGH → LOW** when *either* signal crosses its lower edge
  (bandwidth < 1.20 Mbps, or latency > 180 ms) — degrade eagerly.
- **LOW → HIGH** only when *both* clear the upper edge
  (bandwidth > 2.00 Mbps *and* latency < 120 ms) — recover conservatively.

Because `switch_down < switch_up`, a link hovering between the two never changes
mode. A configurable minimum dwell time adds a second guard against flapping.

## A note on Mininet

The PRD specifies Mininet for link emulation. **Mininet requires Linux network
namespaces and `tc`, so it cannot run on Windows or macOS**, where this prototype
was built.

[`seva/link.py`](seva/link.py) is therefore a faithful in-process stand-in exposing
the same four knobs as Mininet's `TCLink`, with the same semantics:

- **bandwidth** → token bucket, so oversized payloads queue rather than vanish
- **delay** → fixed one-way propagation
- **jitter** → uniform variation around that delay
- **loss** → Bernoulli per-transmission drop

[`scripts/mininet_topo.py`](scripts/mininet_topo.py) builds the equivalent real
topology for a Linux host, reading the same scenario steps from `config.yaml` and
substituting genuine `iperf3`/`ping` telemetry for the emulated probe. A trial
scripted for the emulator reproduces on Mininet without edits:

```bash
sudo python3 scripts/mininet_topo.py --duration 160    # Linux only
```

Both paths are honest about what they are. KPIs from the emulator should be
reported as emulation-based, exactly as PRD §15 requires.

### How the probe measures honestly

A single short transfer across an idle token bucket rides on accumulated burst
credit and reports far more throughput than the link can sustain — an early version
of this code read 20 Mbps on a 7 Mbps link. Real `iperf3` avoids this by saturating
the link and discarding the opening interval. `EmulatedLink.saturating_transfer()`
reproduces that steady state, and the probe now tracks the configured rate to
within 2% with ±7% run-to-run scatter, so the EWMA has realistic input to smooth.

## Configuration

Everything tunable lives in [`config.yaml`](config.yaml) (FR-10, NFR-6) — EWMA α,
both hysteresis thresholds, sampling rate, thumbnail quality, probe interval, and
the full degradation timeline. Encoder thresholds can also be retuned live from the
dashboard or via `POST /api/encoder/tune`, with no restart.

To use your own footage, drop any `.mp4` into `data/videos/`.

## Status against the PRD

**Complete:** all 16 functional requirements, the §9 payload contract, the §10
algorithms, all five §13 KPIs, and the Review 1 milestone list — with the Review 2
adaptive logic and the Review 3 dashboard already working.

**Deliberately not built** (PRD §4.2 scopes these out): physical hardware,
multi-camera fusion, dashboard authentication, model training from scratch, field
deployment, mobile clients.

**Known limitations**, worth stating plainly at review:

- Detection accuracy (mAP) is quoted from the pretrained YOLOv8n COCO checkpoint;
  this prototype does not run a COCO/Cityscapes evaluation pass, so mAP is the one
  §13 KPI not measured here.
- Link behaviour is emulated, not measured on a real cellular or Wi-Fi network.
- Single camera only.
